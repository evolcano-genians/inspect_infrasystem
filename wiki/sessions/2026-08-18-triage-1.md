# 세션 triage-1 (2026-08-18)

## 질문

crashloop-demo 왜 죽는지 triage 해줘

## 결론

**결론:** `crashloop-demo`는 애플리케이션이 의도적으로 종료되도록 구성된 테스트 파드로 보이며, 일시적 장애가 아니라 **반복적인 프로세스 종료** 때문에 `CrashLoopBackOff` 상태입니다.

- 상태: Pod `Running`, 컨테이너 `main`은 `Ready=false`, waiting 사유는 `CrashLoopBackOff`
- 재시작: **11회**, 재시작 백오프는 최대 **5분**
- 이벤트: 컨테이너 재시작 `BackOff`가 **36회** 반복됨(최근 관찰 `2026-08-18T07:41:50Z`)
- 로그: 현재 및 직전 컨테이너 모두 `boom-marker: intentional crash for inspection fixture` 출력
- 종료 코드: 조회 응답에 last terminated state가 없어 **exit code는 확인되지 않음**
- 초기 `FailedScheduling` 1회는 이후 정상 스케줄링되어 현재 장애 원인이 아님
- 이미지 pull/실행은 성공하므로 이미지 문제나 노드 배치 문제도 아님

**다음으로 확인할 것**
- 재조회 시 last terminated state가 노출되는지 확인해 실제 exit code와 종료 사유를 확정
- 파드의 관리 주체(Deployment 등)와 실행 명령 구성을 조회해 의도적 `exit` 설정 여부 확인
