## 결론

AWS dev의 Silver는 **중첩 문서가 아닌 평탄화된 Delta 테이블**입니다. 각 행은 업무 컬럼과 Kafka 추적용 메타컬럼으로 구성되며, tenant는 컬럼이 아니라 `delta.tenant_genians` 스키마로 분리됩니다.

아래 내용은 **2026-08-05 Trino 실측**과 **2026-08-14 파이프라인 소스 분석** 기준입니다. 전체 정확한 `DESCRIBE` 결과는 현재 Trino SQL 도구가 없어 재조회하지 못했으며, 확인된 컬럼만 기재합니다.

### 공통 구조

모든 Silver 테이블에는 원천 업무 컬럼 외에 다음 메타컬럼이 붙습니다.

| 컬럼 | 의미 | 일반 타입 |
|---|---|---|
| `kafka_topic` | 원천 Kafka topic | `varchar` |
| `kafka_partition` | Kafka 파티션 | 정수형 |
| `kafka_offset` | Kafka offset | `bigint` |
| `kafka_timestamp` | Kafka 이벤트 시각 | `timestamp` |
| `ingested_at` | Bronze 적재 시각 | `timestamp` |
| `resource_id` | Registry resource 식별자 | `varchar` |
| `message_key` | Kafka message key | `varchar` |

`tenant_id`는 Silver 컬럼에 포함되지 않습니다. 대신 `tenant_genians`처럼 데이터베이스/스키마 이름으로 tenant를 구분합니다. `raw_value` 원문도 promotion schema에 명시하지 않으면 Silver에서 제거됩니다.

| 컬럼군 | 의미 |

| `kafka_*`, `ingested_at` | 적재 메타데이터 |

확인된 핵심 컬럼은 다음과 같습니다.

| 주요 컬럼 | 의미 | 타입/주의점 |
|---|---|---|
| `nl_nodeid` | NAC 노드 식별자 | 권장 논리 키 |

| `nl_ipstr` | 표시용 IP 문자열 | IP 분석에는 이 컬럼 권장 |
| `nl_ip` | 숫자형 IP 표현 | `bigint`; `nl_ipstr`과 타입 다름 |
| `nl_hostname` | 호스트 이름 | 빈 문자열 처리 필요 |
| `nl_platform` | 탐지된 플랫폼/OS | 장비 분류 |
| `nl_sensor` | 관찰 센서 | 위치·수집 경로 |
| `nl_authuser` | 인증 사용자 | 95.7%가 빈 문자열 |
| `nl_lastactive` | 마지막 활동 시각/epoch | 숫자 캐스팅 필요 가능 |
| `nl_osid` | OS 플랫폼 코드 | EDR `platformcode`와 연계 가능 |
| `nl_pltrustscore` | 플랫폼 신뢰 점수 | 0~100 실분포 확인 |
| `nl_riskscore` | 위험 점수 | 전 행 0으로 현재 분석 가치 낮음 |
| `nl_securitylevel` | 보안 수준 | 전 행 0에 가까운 껍데기 값 |
| `dl_flags` | 단말 상태 플래그 | 쉼표 토큰 목록 |
| `dl_type` | 장비 유형 | 0=단말, 1=센서, 2=정책 서버 |
| `dl_devid` / `nl_devid` | NODELIST↔DEVLIST 연계 키 | 내부 자산 결합 |
| 공통 메타 7개 | 최신 행 선택 | `ingested_at`, `kafka_offset` 사용 |

실사용 시 반드시 다음 방식으로 최신 행을 선택해야 합니다.

```sql
row_number() over (
  partition by upper(nl_mac), nl_ipstr
  order by ingested_at desc, kafka_offset desc
)
```

실제 위험 신호는 점수보다 `dl_flags`의 `NLF_RISKNODE`, `NLF_NOTMEETPATCHSET`, `NLF_AGENTDELETED`, `NLF_HAVEAGENT` 같은 토큰입니다.
