# 세션 web-d6fc9658 (2026-08-18)

## 질문

현재 aws-seoul-clouddev 클러스터 read-only로 분석해서 kind에 띄어서 현재 pc에서 테스트 할 수 있는 환경 만들어줘

## 결론

결론: **현재 PC에 kind 환경을 직접 생성·배포할 수 없습니다.** 이 에이전트는 `aws-seoul-clouddev` 클러스터에 대한 read-only 조회만 가능하며, 로컬 파일 생성·명령 실행·리소스 export 및 Secret 조회는 범위 밖입니다. 또한 전체 클러스터를 그대로 복제하기보다 테스트 대상 네임스페이스를 선별해야 현실적입니다.

- 이번 조회 기준 Kubernetes `v1.32.3`, Ready 노드 5대, 총 `14 vCPU / 약 78 GiB` allocatable이며 실제 노드 메모리 사용량은 약 `27.8 GiB`입니다.
- 핵심 워크로드는 `default`, `nexus-shell`, `monitoring`, tenant 네임스페이스들에 집중되어 있습니다.
- `default`에는 CSM, API Gateway, MySQL/Percona, Backstage 등이 있으며 `nexus-shell`에는 Kafka, Spark, Trino, Hive, PostgreSQL, Loki 등이 있어 전체 로컬 구동에는 대략 `32 GiB RAM` 이상을 권장합니다.
- AWS EBS/EFS provisioner, Calico, AWS DNS/인증서 설정과 사설 `genians/*` 이미지가 사용됩니다. kind에서는 EBS/EFS를 `local-path` 또는 `hostPath`로 대체하고 AWS 연동을 mock 처리해야 합니다.
- ConfigMap 키는 확인했지만 값은 제공되지 않았고, Secret은 [REDACTED] 도구가 없어 registry credential, DB 암호, OAuth 설정 등을 복제할 수 없습니다.
- 현재 확인한 주요 파드는 모두 Running/Ready입니다. 일부 재시작 횟수는 `19~76회`지만 여러 시스템 파드가 동일 시점에 다시 시작한 패턴이어서 현재 CrashLoop보다는 과거 노드 재기동 영향 가능성이 큽니다.

**권장 로컬 구성**
```bash
kind create cluster --name clouddev-local \
  --image kindest/node:v1.32.3
```
그 후 대상 워크로드의 [REDACTED]을 민감정보 제거 후 적용하고, `genians/*` 이미지 pull 권한과 별도의 개발용 Secret을 준비해야 합니다. AWS CSI 및 클러스터용 Calico 리소스는 그대로 적용하면 안 됩니다.

**다음으로 확인할 것**
1. 로컬에서 테스트할 범위를 `default`, `nexus-shell`, 특정 tenant 중 하나로 지정하면 해당 Deployment·Service 연결 관계를 read-only로 상세 분석하겠습니다.
2. 선택한 범위의 스토리지 및 사설 이미지 의존성을 확인해 kind에서 제외·대체해야 할 리소스 목록을 만들겠습니다.
